# План 0031 — наскрізне покриття масивів і приклади

## Мета

Посилити перевірку реалізованого AST-to-AST lowering локальних фіксованих масивів, розширити набір коротких виконуваних прикладів і знайти та виправити підтверджені регресії в межах уже погодженої семантики. Не додавати нових мовних можливостей.

## Обсяг

- Перевіряти source-програми наскрізно через parser, semantic analysis, AST-to-AST lowering, IR verifier, x86-64 backend, системний linker і запуск бінарника.
- Додати focused semantic cases для несумісних типів/довжин масивів, вкладених літералів, помилкової змінюваності, compile-time відомих індексів (включно з layout-query значенням і верхніми межами) та переповнення layout.
- Перевірити поведінку й копіювання за значенням для цілого масиву та вкладеного підмасиву: присвоєння, передавання параметром, повернення, вкладені виклики та мутацію копій.
- Перевірити `array[T, 0]` через присвоєння, аргументи, результати й вкладений layout; індексація нульової довжини має мати compile-time або runtime помилку відповідно до відомості індексу.
- Розширити runtime bounds cases на індекси `0`, `N-1`, `N`, найбільший `uint`, зовнішній та внутрішній індекс вкладеного масиву; перевірити тип винятку й source frame/line.
- Зробити evaluation-order тести спостережними: RHS спочатку, потім base та індекси зліва направо, кожен рівно один раз. Охопити і читання, і indexed assignment.
- Перевірити виклики з масивами та scalar параметрами по обидва боки межі register/stack аргументів, з прихованим result storage і без нього.
- Переконатися, що scalar element loads/stores зберігають IR тип і ширину для підтриманих element types; для поведінки, яку source зараз не може спостерігати без integer casts/comparisons, використовувати стабільний typed-IR/backend контракт замість штучної source-перевірки.
- Додати окремі runnable `.py` приклади для scalar/nested indexing і mutation, value-copy через функції, нульових масивів та runtime bounds exception. Кожен приклад має мати наскрізний тест із перевіреним кодом завершення й очікуваним результатом або діагностикою.
- Оновити README з коротким каталогом прикладів. Не додавати приклади, які не перевіряються тестами.

## Поза обсягом

Глобальні й динамічні масиви, slicing, від'ємні індекси, pointer elements, integer casts/comparison у source, новий синтаксис та зміна погоджених правил array/memory semantics.

## Критерії приймання

- Нові тести відтворюють конкретні вимоги або ризики й перевіряють observable behavior; кожен виправлений дефект спершу має failing test із правильним приводом падіння.
- Копії локальних, вкладених, параметричних і повернутих масивів незалежні; ABI зберігає значення на register/stack межах.
- Динамічні недопустимі індекси не проходять повз перевірку, а trace вказує на відповідний source location.
- Кожен доданий приклад компілюється та виконується у своєму тесті.
- `crystal tool format --check`, `git diff --check` і повний `crystal spec` проходять.
