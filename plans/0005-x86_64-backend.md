# Linux x86_64 Native Backend Plan

## Goal

Generate a Linux x86_64 ELF64 relocatable object file directly from a verified `IrModule`. The backend owns machine instruction selection, register allocation, machine-code encoding, relocations, and ELF object writing. `cc` remains the linker driver.

## Agreed behavior

- Input is the in-memory typed IR. AST-to-IR lowering, semantic analysis, a source compiler CLI, and executable linking are separate work.
- The backend writes ELF64 little-endian `ET_REL` objects for `EM_X86_64` itself; it does not emit assembly or invoke an assembler.
- Follow System V AMD64 calling convention for integer parameters and results. Return values use the ABI result register; calls must preserve stack alignment and account for caller-clobbered registers.
- Implement a linear-scan register allocator from the first slice. Each SSA value receives an explicit machine location: a general-purpose register or a spill slot. Spill only under register pressure or when a value must remain live across a call.
- Values live across a call are spilled around that call in the first allocator. Use caller-saved registers for ordinary allocation so generated functions do not need callee-saved register save/restore yet.
- Lower the current IR operations: `const`, `add`, `sub`, direct internal `call`, and `return`. Preserve the README's unspecified overflow behavior; add no overflow checks.
- A module function's identity remains its `FunctionId`. The object writer maps those identities to ELF symbols and emits relocations for direct internal calls. Export `main` for linking as an executable; keep other first-slice function symbols internal to the object.
- Keep the transformation stages separate: verified IR, x86_64 instruction selection, liveness and register allocation, stack-frame layout, instruction encoding and relocation collection, then ELF serialization. Expose generated object bytes as data and isolate filesystem writes at the output boundary.
- Do not add AST lowering, FFI, conditional control flow, optimizations beyond register allocation, debug information, or a linker implementation.

## Scope

- Add a target-specific backend module that consumes only verified IR and produces ELF64 relocatable object contents.
- Implement the SysV AMD64 parameter locations, call argument setup, return value handling, caller-clobber behavior, and 16-byte call-site stack alignment, including stack-passed integer arguments.
- Implement the x86_64 integer instructions needed for constants, 64-bit addition and subtraction, direct calls, function entry/exit, and return.
- Lay out function code and stack frames, assign spill slots, and emit ELF symbols plus `R_X86_64_PLT32` relocations for internal calls.
- Keep backend failures explicit for invalid IR or unsupported target/input conditions.

## Acceptance criteria

- A valid IR module can be emitted directly as an ELF64 `ET_REL` object without invoking an assembler.
- The object links with `cc` and runs as an executable whose `main` returns the expected process status.
- Tests exercise constants, addition, subtraction, direct internal calls, call-live spills, register-pressure spills, and stack-passed arguments.
- Generated calls obey SysV AMD64 stack alignment and caller-clobber rules; return values and parameters follow the ABI.
- The allocator assigns explicit register or spill locations and spills only when required by pressure or call boundaries; it does not assign every SSA value a stack slot by default.
- No source parsing, AST lowering, semantic analysis, external calls, FFI, branches, or machine-code optimizations are introduced.

## Implementation steps

1. Define the backend result and boundary API, target errors, machine registers, and explicit value-location representation.
2. Lower the current verified IR subset to x86_64 operations with instruction positions and use/definition information.
3. Implement linear-scan intervals for the current single-block functions; handle call clobbers by spilling and restoring live-through values, and allocate spill/frame locations.
4. Implement function prologues and epilogues, ABI argument and result moves, call-site stack alignment, and stack arguments.
5. Encode machine instructions and collect symbol references and call relocations.
6. Serialize `.text`, relocation, symbol, string, and section-name data into an ELF64 relocatable object.
7. Add behavior tests that emit objects from constructed IR, link them with `cc`, and check executable behavior, including spills and internal calls.

## Verification

- Follow test-first behavior development and run focused backend specs plus the full `crystal spec` suite.
- Link generated objects with `cc` and execute the resulting binary to verify observable results.
- Check object format and relocation behavior through successful linking; use available ELF inspection tools only for debugging failures.
- Run Crystal formatting and `git diff --check` before committing.
