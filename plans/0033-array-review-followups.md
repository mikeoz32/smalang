# План 0033 — виправлення граничних випадків масивів

## Мета

Закрити три зауваження рев'ю до `9df4ccc`: перевіряти довжину кожного виміру масиву незалежно від фізичного byte size, додати наскрізний тест array-valued `match` і синхронізувати статуси ADR з уже реалізованим lowering.

## Узгоджена поведінка

- Для цілі Linux x86_64 кожен вимір `array[T, N]` відхиляється під час компіляції, якщо `N` перевищує `Int32::MAX`, навіть коли тип елемента має нульовий storage size. Це стосується вкладених типів.
- `match` може повертати масив із різних локальних масивів у різних гілках; вибране значення зберігає визначену source-семантику копіювання за значенням.
- ADR 0002 та `docs/adr/0001-fixed-size-arrays.md` мають відображати реалізований стан. Copy elision не змінюється в цьому виправленні; чинний ADR 0004 вже дозволяє усувати фізичне копіювання лише зі збереженням поведінки.

## Межі

- Не змінювати source-семантику масивів, IR, backend ABI чи Memory API.
- Не впроваджувати copy elision або інші оптимізації.

## Критерії приймання

- Регресійний тест доводить, що вкладений тип із нульовим byte size та виміром понад `Int32::MAX` відхиляється до IR lowering з діагностикою.
- `.py` integration test компілює й запускає функцію, яка повертає різні локальні масиви з гілок `match`, і перевіряє значення обох гілок.
- Статуси ADR більше не стверджують, що вже реалізований array AST desugaring відкладений.
- `crystal tool format --check`, `git diff --check` і `crystal spec` проходять.

## Кроки

1. Додати regression test для надмірної довжини виміру з нульовими елементами та підтвердити поточний пропуск.
2. Перевіряти межу довжини рекурсивно для кожного вкладеного array type, не покладаючись лише на загальний byte size.
3. Додати й виконати array-valued `match` integration test із різними локальними масивами в гілках.
4. Оновити статуси ADR 0002 та ADR 0001 для fixed arrays.
5. Повторити перевірки та незалежне рев'ю повного diff.
