# ADR 0003: Unsafe-операції з пам'яттю

Статус: прийнято. Початковий зріз реалізує скалярні raw-вказівники для Linux x86-64.

## Контекст

Runtime, алокатори, контейнери й майбутній C FFI потребують доступу до пам'яті за адресами. Такі можливості мають бути явними; назва або розташування модуля не надає особливих привілеїв.

## Рішення

- `ptr[T]` — типізована raw-адреса, а не власник. Наразі `T` може бути наявним скалярним типом: `bool`, `int`, `uint` або fixed-width integer.
- Вказівник є копійованим значенням адреси. Копія не дублює пам'ять і не створює другого власника. Після `free` усі копії застарілі; подальше використання є відповідальністю unsafe-коду.
- Вказівники дозволені в локальних оголошеннях, параметрах і результатах функцій. Неявних перетворень між `ptr[T]` і цілими типами немає.
- `unsafe:` позначає блок операцій із пам'яттю. Блок користується спільною пласкою областю імен функції; вкладені блоки та `return` усередині них не підтримуються. Unsafe-функцій поки немає.
- `alloc(value)` виділяє пам'ять для одного скаляра, відразу записує початкове значення й повертає `ptr[T]`. Явне оголошення вказівника задає тип літерала, наприклад `address: ptr[int] = alloc(42)`.
- `load(address)` читає значення типу `T`; `store(address, value)` записує значення того самого `T`; `free(address)` звільняє одноелементне виділення. Усі операції дозволені лише всередині `unsafe:`. `store` та `free` — окремі statements; довільні expression statements не додаються.
- Імена `alloc`, `load`, `store` і `free` зарезервовані для вбудованих операцій і не можуть бути назвами функцій.
- Невдала алокація породжує runtime-помилку `OutOfMemory`. Якщо runtime не може виділити пам'ять і для запису винятку, він без алокації друкує `Uncaught exception: OutOfMemory` із поточним стеком викликів і завершує процес із кодом 1.
- У Linux x86-64 raw-адреса займає 64 біти. Цілі в пам'яті займають розмір відповідно до оголошеної ширини; `bool` займає байт і зберігається канонічно як `0` або `1`.
- Поточний backend використовує прямі `mmap`/`munmap` syscall-и для одноелементних виділень. Тип вказівника не доводить валідність, вирівнювання, межі чи час життя адреси. Unsafe-код відповідає за ініціалізацію, доступ і звільнення.
- Тип `ptr[T]` відокремлений від `array[T, N]`. Unsafe API використовує функції; UFCS або методи не потрібні.

```python
def read_and_free(address: ptr[int]) -> int:
    unsafe:
        value: int = load(address)
        free(address)
    return value
```

## Наслідки

- Перевірка типів і unsafe-контексту відхиляє невалідні програми під час компіляції; валідність самої адреси лишається за програмістом.
- Не додаються перевірки меж, pointer arithmetic, casts, dynamic buffers, custom allocators, owning wrappers, автоматичний cleanup або ownership tracking.
- Масиви та інші нескалярні pointee, C FFI й деталі інших платформ розглядаються окремими рішеннями. Будь-яке їхнє додавання має зберігати спільну модель явних unsafe-операцій.
