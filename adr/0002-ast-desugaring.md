# ADR 0002: Desugaring у межах одного AST

Статус: прийнято; спільний AST-to-AST pass pipeline реалізовано для локальних масивів відповідно до ADR 0004. Інші застосування цього напрямку визначатимуть окремими рішеннями.

## Контекст

Розвиток source-синтаксису не повинен вимагати підтримки кожної високорівневої конструкції в IR lowering. Частина низькорівневих операцій також буде доступна користувачу через unsafe API.

## Рішення

- Використовуємо одну модель AST зі спільним набором високорівневих і низькорівневих типів вузлів. Окремий Core AST не вводимо.
- Compiler passes розгортають синтаксичний цукор в простіші конструкції того самого AST. Кількість вузлів програми може зростати, а кількість їхніх видів, що залишаються перед IR lowering, зменшується.
- Перевірки типів, ownership, ініціалізації та інших source-правил виконуються до розгортання, яке видаляє потрібний для цих перевірок зміст. Сам ownership не доводить коректність індексів або ініціалізації пам'яті.
- Кожен pass має передумови й постумови: які вузли він приймає, які усуває та які гарантії зберігає. Семантичні факти для змінених вузлів оновлюються або обчислюються заново за контрактом проходу.
- Перед IR lowering перевіряємо, що AST містить лише підтримувані цим етапом конструкції й задовольняє його інваріанти.
- Згенеровані вузли зберігають зв'язок із source locations для діагностики та налагодження.
- Низькорівневі вузли можуть походити з користувацького unsafe-коду або бути породжені compiler pass. Користувацькі операції перевіряються за unsafe-правилами; коректність згенерованих операцій є відповідальністю lowering-проходу. Наявність згенерованих операцій не дає навколишньому source-коду дозволу на unsafe.

```text
Parser → AST → source semantic/ownership checks
             → AST desugaring passes → invariant checks
             → typed IR lowering → backend
```

## Наслідки

Застосування цього конвеєра до масивів і каталог примітивів пам'яті визначає [ADR 0004](0004-array-desugaring-and-memory-primitives.md).

- IR lowering обробляє менший, регулярніший набір конструкцій.
- Внутрішні операції пам'яті не потребують прямого source-еквівалента для кожного вузла; частина операцій має публічний unsafe API, описаний в ADR 0003.
- Конкретні конструкції, порядок проходів і представлення семантичних фактів визначаються під час проєктування відповідних фіч.
